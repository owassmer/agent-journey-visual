Every number is either\ncomputed from a file on disk or read from a page actually fetched. Anything\nthat could not be retrieved is listed as a retrieval failure, never smoothed\nover. Fabricating a plausible government statistic is the one unrecoverable\nfailure mode in this class of work — the reader is often a domain expert who\nknows the real figure.\n\n## When to use\n\n- \"Produce a domain brief on <federal/state program> so I can pick what to build.\"\n- Grounding a demo, portfolio artifact, or build-to-apply submission in a real\n  regulated domain (paired with `connor-job-search` for the application framing).\n- Evaluating whether a public dataset can actually support a claimed analysis.\n- Matching a population against an exclusion / debarment / sanctions / enforcement\n  registry, and deciding what the hits actually mean — see\n  `references/watchlist-match-adjudication.md` before reporting any count.\n- Deciding go/no-go on adding a second federal source (USAspending, SAM.gov,\n  FAC, IRS BMF) — i.e. \"can these actually be joined, and on what key?\"\n- Any task whose deliverable asserts government statistics, agency workflows,\n  or regulatory mechanics.\n- **Attacking a source set rather than building one** — \"adversarial sweep,\"\n  \"find the blind spots,\" \"what did we miss,\" \"challenge the sources we chose,\"\n  or reviewing a grounding brief / feature set / scoring design before it meets a\n  domain expert. See `references/adversarial-source-review.md` for the playbook:\n  severity-first ordering, the three supersession questions, attacking the\n  outcome variable before the features, invented-strata detection, mapping terms\n  onto the regulation's own selection criteria, and sustaining a deferral by\n  replacing its reasoning.\n- Assembling a **regulatory corpus as a loadable artifact** (RAG index, ontology\n  object type, citable chunk store) rather than a prose brief — same sourcing\n  discipline, different output shape. See §4b.\n\nDon't use for: vendor/SaaS API research (`third-party-integration-research`),\nacademic papers (`research-paper-analysis`), or fixture-chain audits\n(`document-data-lineage-audits`).\n\n## Workflow\n\n### 1. Find the data — assume the documented URL is stale\n\nFederal data portals migrate constantly and the canonical link in every blog\npost, prior brief, and model memory is frequently a 404.\n\n- **Try `https://<portal>/data.json` FIRST.** Federal portals publish a DCAT-US\n  catalog there, and **it survives the CKAN→Drupal migration that kills the CKAN\n  API.** Verified: `data.sba.gov/api/3/action/package_list` → **404**, while\n  `data.sba.gov/data.json` → **200**, 88 KB, listing all 25 datasets with a\n  `distribution[]` array of direct `downloadURL`s per file. It surfaced files\n  (including an embedded Tableau dashboard URL) that appear nowhere in the\n  rendered HTML. This is strictly better than scraping.\n- **Do not trust CKAN.** Many `.gov` portals have migrated off CKAN to Drupal.\n  `data.sba.gov/api/3/action/package_show` returns HTML; `catalog.data.gov/api/3/action/package_search`\n  returns `{\"detail\":{},\"message\":\"Not Found\"}`. Probe the API once; when it\n  fails, stop trying API variants and fall back to `data.json`, then to\n  **scraping the landing page**.\n- **Cross-check `data.json` against the scraped `/dataset` index.** Agreement\n  across both is your completeness proof, and it lets you state the negative with\n  a bound (\"no lender roster among the 25 catalog datasets\") instead of vaguely.\n- **Slug hyphenation is a common trap** — `/dataset/7-a-504-foia` 404s while\n  `/dataset/7a-504-foia` works. Get the real slug from the portal's index page\n  (`/dataset`, `/oca-datasets`, program-office landing pages) by grepping hrefs.\n- **Then grep the landing page for file extensions directly:**\n  `grep -oE 'href=\"[^\"]*\\.(csv|xlsx|xls|zip|pdf)[^\"]*\"' page.html | sort -u`\n  This is faster and more reliable than any catalog API.\n- **Check whether filenames are date-stamped.** SBA embeds `asof_YYMMDD`, so the\n  URLs are *not stable across refreshes*. Any pipeline must re-scrape the\n  landing page rather than hardcode a URL. Say this in the brief — it is a real\n  engineering constraint the reader will care about.\n\nCompletion criterion: real bytes on disk with verified sizes, or an explicit\nstatement of what could not be downloaded and why.\n\n### 2. Download and profile for real — never describe a schema you haven't read\n\n- Download to a project-local `data/` dir. Report byte counts.\n- Read the data dictionary (`.xlsx` dictionaries read fine via `read_file`).\n- Print the **actual header**, the **actual row count**, and **one real row\n  field-by-field**. Row-1 inspection routinely surfaces bugs the dictionary\n  denies.\n- Profile deliberately for: status/outcome distributions, null rates per column,\n  values that contradict the published dictionary, date ranges, entity counts,\n  and cross-field contradictions (terminal status vs missing terminal date).\n\n### 3. Write the \"what is NOT in the data\" section — this is the highest-value section\n\nAnalysts and domain readers judge a brief on its honesty about gaps. For every\ndataset, enumerate the fields whose *absence* constrains what can be claimed:\nno delinquency status, no outstanding balance, no recoveries, no event log, no\nthird-party score, masked/exempt records. Then state precisely which downstream\nmetrics are therefore proxies rather than measurements.\n\n### 4. Get the regulation from primary sources\n\nThese endpoints work and return clean text:\n\n- **eCFR full part as XML:**\n  `https://www.ecfr.gov/api/versioner/v1/full/<YYYY-MM-DD>/title-<NN>.xml?part=<NNN>`\n  Fetch the whole part and slice to the section you need; `subpart=` sometimes\n  works but `subject-group=` returns 400.\n- **Federal Register search API:**\n  `https://www.federalregister.gov/api/v1/documents.json?conditions[term]=<query>&per_page=10&fields[]=title&fields[]=publication_date&fields[]=html_url&fields[]=abstract`\n- **Federal Register full plain text** (the good one):\n  `https://www.federalregister.gov/documents/full_text/text/<YYYY>/<MM>/<DD>/<docnum>.txt`\n  FR notices frequently contain the *complete model specification* an agency\n  uses — variable lists, segmentation, functional forms. This is the single\n  richest vein for oversight/scoring domains.\n- **paymentaccuracy.gov** agency pages (`https://paymentaccuracy.gov/agency/<CODE>`\n  — note **no `www.`**, which 302s) are server-rendered and yield agency\n  improper-payment rates, confirmed fraud, recovery amounts and rates, the\n  explicit **non-compliant program list**, the agency's **certified corrective\n  actions**, named accountable officials, and the agency's own verbatim\n  admissions. Charts are client-side (`chartBundle.min.js`) with no discoverable\n  data endpoint — **program-level rates are not retrievable this way.**\n  **This page is the PIIA \"accompanying materials\" and it carries figures that\n  are provably absent from the AFR** — see §4d.\n- **Agency OIG reports:** for a single agency, harvest the corpus from the\n  agency's own `sitemap.xml?page=1..N` (every report is at\n  `/document/report-<NN>-<NN>-<slug>`), then resolve each landing page to its PDF\n  by grepping `href=\"/sites/default/files/[^\"]*\\.pdf\"`. Extract with\n  `pdftotext -layout` — OIG executive summaries are two-column and interleave into\n  gibberish without `-layout`. The executive summary carries the headline\n  estimate, the quantified monetary impact, and the methodology caveat. Reach for\n  oversight.gov when the question spans **multiple** agencies; for one agency the\n  sitemap is faster and complete.\n- **Agency SOPs / policy manuals:** discover via `sitemap.xml?page=1..N`, not the\n  site's own search UI. Drupal `.gov` document search pages routinely render the\n  same unfiltered list for every query (filtering is client-side) and their\n  JSON:API returns 401. Grep the sitemap for `/document/.*<sop|manual|notice>.*`\n  to get real slugs — and read the whole grep output, since it surfaces on-point\n  documents that weren't on the task list.\n\nRead the fetched text rather than summarizing it. The highest-value material is\nusually a **structural asymmetry** between two adjacent paragraphs (who is\ncovered by (a) but not (b)), a **hard deadline** stated in business vs calendar\ndays, or a **delegation hook** (\"as set forth in notices\") telling you the real\nspecification lives in a Federal Register document.\n\n### 4a-bis. Retrieve the rule *as of the event date*, and chase the routing paragraph\n\nTwo mechanical habits that turn \"I read the rule\" into \"I read the rule that\napplied.\" Both are cheap; skipping either produces a confidently wrong brief.\n\n**Point-in-time retrieval — use the browse URL, not only the versioner API.**\n\n```\ncurrent      https://www.ecfr.gov/current/title-13/part-121/section-121.301\nas-of-date   https://www.ecfr.gov/on/2023-04-09/title-13/part-121/section-121.301\n```\n\nThe `/on/<YYYY-MM-DD>/` path renders the version in force that day as ordinary\nHTML and extracts cleanly — no XML parsing, no `subpart=`/`subject-group=`\nfiddling. Pair it with the section's amendment history, which eCFR gives you\ntwice on the page: the **Timeline** control (every amendment date with\n`view change introduced` / `compare to most recent`) and the **bracketed FR\ncitation list** at the foot of the section. Diff current against the last\npre-amendment version; that diff is the artifact.\n\n**A panel spanning an amendment is two populations.** Any brief asserting what a\nrule required must say which version governed which rows. Downstream consequence\nand the candidate-level fix: `oversight-pattern-screening` §11b.\n\n**Then chase the cross-reference routing — the section you were handed is often\nnot the operative one.** Two shapes, both hit in one session:\n\n- **A routing paragraph redirects the whole program.** \"(a)(8) For applicants in\n  SBA's Business Loan, Disaster Loan, and Surety Bond Guarantee Programs, the\n  size standards and bases for affiliation are set forth in § 121.301.\"\n  (13 CFR 121.103(a)(8)) — so none of the famous, universally-cited control tests\n  in 121.103 govern 7(a); only its **exceptions** subsection is imported. Reading\n  the general section and stopping produces a brief wrong end to end.\n- **The number everyone quotes sits in a different Part and measures a different\n  quantity.** The per-transaction maximum was in one Part; the limit binding a\n  *group* was in another and denominated in **guaranty exposure**, not gross\n  amount. Restating the finding in the correct quantity made it both legally\n  right and materially larger.\n\nGrep every retrieved section for `see §`, `as set forth in`, `as defined in`,\n`except as` — and quote the routing sentence verbatim.\n\n**Read the amending rule's preamble, not only the codified text.** The FR\ndocument says what changed and why in the agency's own voice, and that reasoning\nis usually the strongest statement of the benign explanation for whatever you are\nscreening. federalregister.gov HTML is bot-blocked; use the API:\n\n```bash\ncurl -s \"https://www.federalregister.gov/api/v1/documents/<DOCNUM>.json\\\n?fields[]=title&fields[]=publication_date&fields[]=effective_on\\\n&fields[]=citation&fields[]=raw_text_url\"\n```\n\n**`effective_on` is routinely weeks after `publication_date`** — split vintages\non the former.\n\nWorked example (vintage split, both routing traps, and a public\nownership-data availability matrix):\n`references/regulatory-vintage-and-ownership-data-availability.md`.\n\n### 4d. Agency corrective actions live in three tiers — the AFR is usually the weakest\n\nWhen the deliverable needs \"the agency's own commitment to fix X\" (a corrective\naction, a remediation plan, an accountable official), do **not** stop at the\nAgency Financial Report. Under PIIA / OMB M-21-19, the citable material is split:\n\n1. **paymentaccuracy.gov/agency/\\<CODE\\>** — agency-*certified* corrective actions,\n   non-compliant program list, recovery figures, accountable official. Primary.\n2. **The OIG's annual \"Independent Auditors' Report on … Compliance with the\n   PIIA\"** — the *recommendation* tier 1 responds to, with deficiency numbers and\n   page cites. Strongest citation of the three.\n3. **The AFR's MD&A → OIG Management Challenges narrative** — the agency\n   restating the finding in its own voice. Good corroboration, weak alone.\n\nIn OIG PIIA reports, read the parenthetical tag on each recommendation: a rec\nending `(Deficiency 7 & 10; FY2023 Recommendation 9)` is a **carry-forward**,\ni.e. still open across multiple fiscal years — materially stronger than a\nfirst-year finding because it proves persistence.\n\nBefore citing the better source, **grep the AFR for the figure and report the\nzero-hit result**. Proving the commonly-cited document does not contain the\nnumber is what turns \"I found a source\" into a defensible correction. Verified\nrecipe, tier map, and the SBA figures are in\n`references/piia-improper-payment-sourcing.md`.\n\n### 4b. If the deliverable is a corpus, not a brief\n\nWhen the ask is a loadable artifact — RAG index, ontology object type, citable\nchunk store — see `references/regulatory-corpus-chunking.md` for the verified\npipeline: eCFR XML hierarchy, FR `full_text_xml_url` parsing, the chunk schema\n(including the `granularity` column that lets findings pull pinpoint cites while\nthe chatbot pulls section context), structural-vs-heuristic chunking, and the\nround-trip verification pass.\n\n**If the corpus must answer \"what did the rule say on date D?\", or if it will be\nfetched from a restricted-egress runtime** (Foundry external transform, VPC with\nan allowlist), read `references/point-in-time-regulatory-retrieval.md` **before**\nchoosing sources. It carries the proof that GPO annual editions return a\n*different legal standard* than eCFR point-in-time for the same mid-year date,\nthe eCFR historical floor and its silent-404 failure mode, the three-call\nprovenance chain (text → governing amendment → FR citation), the independent\nCFR-clock vs SOP-clock resolution, the \"Variations of this document\" block as a\npublisher-maintained version archive, and the verified-endpoint-manifest +\nredirect-audit discipline for egress policies.\n\n### 4b. Escalate retrieval before declaring anything unavailable\n\n**Rung 0 — verify what you actually downloaded, before parsing it.** A blocked\nfetch does not fail loudly; it saves the rejection page under whatever filename\nyou gave it. `curl -o handbook.pdf` against a bot-blocked host yields a 4–8 KB\nfile that `file -b` reports as \"HTML document text\", and your PDF parser then\nreturns 0 pages or one page reading \"The requested URL was rejected.\" Always\nchain the check before you start extracting:\n\n```bash\ncurl -sL --max-time 90 -A \"Mozilla/5.0\" -o out.pdf \"$URL\"\necho \"$(du -h out.pdf | cut -f1) $(file -b out.pdf | cut -c1-40)\"   # want: \"PDF document\"\n```\n\nIf it is HTML, move to the next mirror instead of debugging the extractor.\nSearch results usually surface 3–6 mirrors of the same document (university\ncourse pages, `.eu` repositories, agency mirrors, Semantic Scholar) — try them\nin that order; publisher-adjacent CDNs block hardest. Note that *open access*\ndoes not mean *fetchable*: a CC-BY paper can be 403 at both the publisher and\nthe funding body's own repository.\n\n**Last rung — when the primary is genuinely paywalled, go to the reference\nimplementation, not to a summary.** Package vignettes, CRAN reference manuals,\nStata module docs, and official software ports routinely restate a method\nfaithfully enough to implement *and* quote — often carrying the exact formulas,\nparameter conventions, and a worked numeric example that the paper itself only\ndescribes in prose. Grade those `PROVISIONAL` and name the artifact you used. A\nquoted formula from an implementation is worth more to a reviewer than a\nparaphrase of an abstract.\n\n**A source is not unavailable until every rung has been tried.** Most \"blocked\"\ngovernment sources in practice are a curl-shaped problem, not a data problem.\n\n1. **curl** — fast, scriptable, right for APIs and static files.\n2. **A real browser** (`browser_mcp`) — defeats Akamai/Cloudflare/bot challenges\n   that beat curl at every user-agent, and additionally clicks buttons, fills\n   forms, and triggers file downloads that no HTTP client can reach.\n3. **A registered API key** — a 404 or 406 from a documented endpoint usually\n   means unauthenticated, not nonexistent. Registration is typically free.\n4. **A bulk download** — many agency search UIs have a \"Download All\" / \"Export\"\n   control that emits the entire table. Always look for one *before* paginating\n   an API or scraping result pages.\n5. **Secondary sources for leads only** — news, aggregators, and search-engine AI\n   summaries are excellent at telling you *which agency and which docket* to look\n   at. Then go back to the primary source for the citation. Never cite the\n   secondary source as the fact.\n\nThe full technique set — shadow-DOM form handling, download capture, the\nlead-then-verify loop — is in `references/browser-retrieval-escalation.md`.\n\n**Read the block's response headers before choosing a rung.** A 403 body tells\nyou nothing; the headers name the mechanism and tell you which rung will work.\n`server: cloudflare` + `cf-mitigated: challenge` + a `critical-ch:\nSec-CH-UA-*` list means a JS challenge plus Client Hints — **user-agent spoofing\nis structurally incapable of passing it**, at any string, so skip straight to a\nreal browser instead of burning a dozen requests cycling UAs. Also check for a\n*sibling host on a different stack*: `www.ffiec.gov/npw/*` is 403 at every path\nwhile `cdr.ffiec.gov/public/` and the Chicago Fed's BHC mirror return 200 to\nplain curl with overlapping content. Verified detail in\n`references/bank-regulator-identity-apis.md` §3.\n\n**Finish the ladder before switching tasks.** The characteristic failure is\nrunning one round of probes, collecting a handful of 403s and connection resets,\nand then quietly drifting back to a more comfortable analytical task with the\nretrieval problem still open. Half a diagnostic reads as a completed one and its\nconclusions get inherited as fact. Either exhaust the ladder or state plainly\nthat retrieval is still unresolved — never let it lapse silently.\n\n**Fix the tooling yourself; don't hand back a menu.** When the working posture is\n\"go get the data,\" the answer is to inventory what is actually configured in the\nenvironment and use it — not to present a list of candidate search providers for\nselection. Enumerate available tools *before* concluding a capability is missing;\nin this session the tool that solved everything had been configured the whole\ntime and simply hadn't been called. Escalate to the user only for actions with\nreal side effects: anything touching billing, credentials, or account state.\n\n### 4c. Check that you are searching the right government\n\nA missing enforcement record is more often the wrong venue than a nonexistent\nevent. **Administrative enforcement against a regulated entity lives at that\nentity's own regulator, not at DOJ.** Banks → FDIC/OCC/Federal Reserve/NCUA\nenforcement-order systems. Securities firms → SEC/FINRA. Health providers →\nHHS-OIG exclusions. DOJ only appears when there was a criminal prosecution or a\ncivil FCA settlement, which is a small minority of cases.\n\nSearching justice.gov for what was an FDIC administrative action returns nothing\nand looks exactly like \"the event did not happen.\" Before concluding a claimed\nenforcement action is unsupported, enumerate the plausible regulators and check\neach one's own order system. See the reference file for the major ones and their\nbulk-download paths.\n\n**And some regulators never publish at all.** SBA lender enforcement is\nnotice-to-lender plus administrative appeal with **no publication step anywhere\nin 13 CFR 120 Subpart I** — so absence of a public record is not evidence of\nabsence of enforcement. `references/enforcement-order-status-and-registries.md`\ncarries the full regulator↔identifier map (cert / charter / RSSD / NMLS), the\nworking OCC bulk-export URLs, the proof-of-non-publication recipe, and the\nmethod for deciding whether an order is still in force.\n\n### 5. Map users to *named* workflows and two-sided error costs\n\nFor each user, produce: the named workflow (as the agency calls it), the\ndecision, the current tooling pain, and the cost of being wrong **in both\ndirections**. A brief that only quantifies missed fraud reads as naive; the\nfalse-positive burden (examiner-weeks, response clocks, appeals, program\nexit, blocked legitimate payments) is what makes it operational.\n\nPrefer regulation-sourced workflow names over invented ones. The CFR names the\noffices, the review types, and the response deadlines.\n\n### 6. Quantify with a verification marker on every claim\n\nMark each figure explicitly:\n- computed from a downloaded file this session,\n- read from a page actually fetched, or\n- **not verified** — with the reason.\n\nEnd the brief with an **Access failures** table listing every URL that failed\nand the status code. This converts a limitation into a credibility signal.\n\n### 7. Bring real analytic rigor, then show the naive version failing\n\nSee `references/outcome-data-analytics-rigor.md` for the reusable techniques:\nright-censoring correction, cohort/vintage tables, era-stratified peer cells,\nactual-vs-expected peer standardization, entity-name instability, and\nproxy-vs-measurement discipline. **If a prior session produced a favorable\nbacktest, §3b-i is mandatory reading before you cite it** — it carries the\nreplicate-then-extend protocol and a worked example where doubling the sample\nturned a \"2× enforcement lift\" into AUC 0.44.\n\nThe most persuasive artifact in a grounding brief is **the naive metric and the\ncorrected metric side by side**, where the naive one produces an obviously wrong\nconclusion. It demonstrates domain knowledge in one table.\n\n### 6b. When the lookup table doesn't exist, reconstruct it from a sibling program\n\n\"Does the agency publish a roster keyed to `<ID>`?\" is answered by construction,\nnot by search. If the catalog has no such dataset, **look for the same identifier\nin a sibling program's release** — a different program run by the same agency\nfrequently publishes the same internal ID *alongside* descriptive attributes,\nbecause that program's disclosure rules were written separately.\n\nVerified: SBA publishes no lender roster, but PPP FOIA carries\n`OriginatingLenderLocationID`/`ServicingLenderLocationID` **with lender name and\nfull address** in the same keyspace as the 7(a)/504 `LocationID`. Streaming all\n14 PPP files reconstructed a 6,044-row roster covering 88.6% of 7(a) lenders and\n**97.42% of loan volume**.\n\nReport **both entity-level and volume-weighted coverage** — the gap between them\nis the finding, and the unmatched residue is usually a systematically different\npopulation worth profiling rather than dropping. Recipes, the zero-padding trap,\nand the streaming/encoding pattern are in `references/public-data-portal-recon.md`.\n\n### 7b. Decide join feasibility BEFORE adopting a second data source\n\nAny time the plan is \"combine dataset A with dataset B,\" the first deliverable is\na go/no-go on the join key, not an integration. Federal award systems key on UEI;\nFOIA/program releases frequently have **no entity key at all**. Answer these in\norder:\n\n1. Does the program dataset contain *any* assigned identifier? (Print the header\n   — do not assume.)\n2. Does the **source agency's own submission to USAspending** populate the\n   identifier? If the government's own copy is null, no crosswalk exists and the\n   question is closed. This is the strongest available disproof — reach for it\n   first instead of enumerating candidate crosswalk sources.\n3. If no identifier: can a **deterministic composite key** (exact equality on\n   3–4 fields) be built, and what is its *measured* collision rate on the real\n   file?\n4. If only fuzzy matching remains: is the candidate set small enough that every\n   match can be manually verified and cited? If not, decline the source.\n\nReport a **GO / NO-GO table with one row per candidate join**, each verdict tied\nto a specific observed API response. Allow `CONDITIONAL GO` / `QUALIFIED GO` —\na flat yes/no hides the useful middle. Full verified detail on SAM.gov,\nUSAspending, and the six dead crosswalk candidates is in\n`references/federal-entity-crosswalk-feasibility.md`.\n\n### 7c. Mining GAO / Inspector General reports when the brief must ground a system design\n\nWhen the ask is \"read audit report X in full and extract only what bears on the design of system Z,\" the\ndeliverable is a disposition list, not a summary: numbered findings, each with a verbatim quote, a page\ncite, and an explicit **ADOPT** / **PRE-EMPT** / **IGNORE** tag. PRE-EMPT means the finding will be used\nagainst the proposed design, so cite it yourself first and state how the design answers it.\n\nFour things that change the whole framing and are easy to miss:\n\n- **Always pull the GAO product page (`gao.gov/products/gao-XX-XXX`), not just the PDF.** Its\n  recommendations table carries per-recommendation status. If every recommendation is\n  `Closed – Implemented`, the report is not a gap to fill — reframe the build as an independent\n  public-data replication of a function the agency now performs with non-public inputs, and adopt the\n  agency's current vocabulary from the closure narratives.\n- **oversight.gov PDF links silently return the site homepage as HTML** with HTTP 200 under the `.pdf`\n  filename you requested; a browser User-Agent does not help. Always `file` the download, then fetch the\n  issuing agency's own mirror instead (find it by grepping the agency landing page for `href=\"*.pdf\"`).\n  gao.gov PDFs resist plain curl but render through `web_extract` with a large `char_limit`.\n- **A recent IG report's footnotes are the cheapest authoritative confirmation of SOP/manual currency** —\n  cited in present tense with effective dates and no successor named. Harvest the whole instrument family\n  in one pass.\n- **Hunt adversarially for prior art that already tested your proxy variable and found it wanting**, for\n  the outcome variable prior evaluations used (and whether it is public), for the effect-size ceiling the\n  real model achieved, and for any crude single-ratio benchmark the auditor showed matching the elaborate\n  model — that benchmark becomes mandatory.\n\nFull playbook, including page-tagged PDF extraction, recovering truncated table cells, scope discipline\nfor program-scoped reports, and borrowing the auditor's hedged vocabulary and Limitations/\"Use of\ncomputer-processed data\" sections: `references/oversight-audit-report-mining.md` (and, for reconciling a held corpus against the full published archive — coverage, per-year counts, citation custody — `references/corpus-coverage-reconciliation.md`).\n\n### 8. Verify the numbers before shipping\n\nResearch dirs have no test suite. Write a temporary script under the OS temp dir\nwith a `hermes-verify-` prefix that **re-derives the headline statistics from\nthe raw files with independent code** — do not import the analysis script, since\nthat only proves it runs twice. Assert exact expected values, print PASS/FAIL,\nexit non-zero on failure, then delete the script. Report it explicitly as\nad-hoc verification, not a green suite.\n\n## Output shape\n\n1. **Bottom line** — the single recommended operational decision, with 3–4\n   reasons, one of which should be the government's own admission that this\n   decision is broken.\n2. **The dataset** — working URLs, cadence, row counts, full schema, one real\n   row, what IS present, what is NOT present, verified data-quality defects.\n3. **Users and decisions** — named workflows, two-sided error costs.\n4. **The oversight/regulatory regime** — cited section by section.\n5. **Quantified problem statements** — grouped by verification status.\n6. **Credible analytics** — including a naive-vs-sophisticated scorecard.\n7. **What makes a demo look expert** — concrete, numbered, demo-able.\n8. **Access failures** — explicit.\n9. **Local artifacts** — tree of what's on disk.\n\nReturn a condensed version in chat; write the full brief to disk.\n\n## Common pitfalls\n\n1. **Treating an HTTP 403 as evidence the data is unavailable.** It is evidence\n   the *tool* was wrong. `gao.gov`, `justice.gov`, and `oversight.gov` return\n   Akamai challenges to curl at every path and every user-agent — and all of them\n   load fine in a real browser. A prior version of this skill recorded\n   \"gao.gov is 403, mark the figures unverified,\" and that hardened into months of\n   needlessly unverified claims until someone finally tried the browser. **Run the\n   full escalation ladder in §4b before writing \"unavailable\" anywhere.** Only\n   after the ladder is exhausted may a figure be marked unverified — and then say\n   which rungs were tried. Never recite a remembered statistic in place of a\n   retrieved one.\n2. **Trusting the data dictionary over the data.** Published dictionaries lie.\n   `RevolverStatus` was documented `0=Term, 1=Revolver` and actually contains `Y`.\n   `LoanStatus` is `\"P I F\"` in one file and `\"PIF\"` in another. Always diff the\n   dictionary against observed values and report the contradictions — they are\n   findings, not noise.\n3. **Unioning sibling datasets that look similar.** Two programs published\n   together can have materially different schemas and credit structures. Check\n   column counts and semantics before concatenating.\n4. **Treating an entity-name column as a stable key.** Fields described as \"the\n   institution the record is *currently assigned to*\" are rewritten by mergers,\n   silently reattributing history. Note the distinct-name vs distinct-ID count\n   mismatch and handle it.\n5. **Ignoring masked records.** FOIA/privacy exemptions frequently mask the\n   *live, healthy* population. Excluding masked rows from a denominator inverts\n   the result. Compute the masked share and lead with it.\n6. **Including never-funded records in exposure denominators.** Cancelled and\n   undisbursed rows are not exposure.\n7. **Shell backgrounding in a foreground terminal call.** A `for ... & done; wait`\n   loop is rejected by the terminal tool. Use a sequential loop, or\n   `background=true` with `notify_on_complete`. Sequential curl of a few hundred\n   MB is fast enough; don't fight it.\n8. **Dumping fetched HTML into context.** Save to files, strip tags with a small\n   reusable script (drop `<script>`/`<style>`, convert block tags to newlines,\n   `html.unescape` twice for eCFR double-encoding), then grep. See\n   `scripts/fetch-and-strip.sh`.\n9. **Reporting an agency workflow from memory.** Office names, review types, and\n   deadlines are all in the CFR. Quote them.\n10. **Leading the brief with the dataset instead of the decision.** The\n    deliverable answers \"what should someone decide differently,\" not \"here is\n    what's in the file.\"\n11. **Reading an empty API response as a data gap.** A deprecated endpoint\n    returns the same empty body for every input. Always probe a **known-good\n    control value** before writing \"no data exists for this program.\"\n12. **Logging status codes without reading error bodies.** The useful answer is\n    often *inside* the failure: an invalid `sort` on USAspending returns the full\n    list of legal field names; a 406 from SAM.gov names the exact `Accept` header\n    required. Print the body on every non-2xx.\n13. **Concluding a keyed API is closed without probing the public UI's own\n    backend.** When the documented API demands a key, the SPA's XHR endpoint is\n    frequently unauthenticated and returns the same records.\n14. **Rejecting a crosswalk candidate on access when the real problem is\n    coverage.** Nonprofit-only, contractor-only, or ≥$750k-spend registries fail\n    on **population mismatch** and would still fail if fully open. Lead with\n    coverage or the reader assumes a key would fix it.\n15. **Treating a name+address-derived hash as a join key.** `recipient_id` and\n    similar surrogate hashes look like identifiers but are computed from the same\n    fuzzy fields; joining on one is fuzzy matching with extra steps. Say so.\n16. **Silently correcting regulatory text.** Official sources contain typos\n    (13 CFR 120.524(e): \"all loan servicing ad liquidation actions\"). Quote them\n    verbatim and footnote the defect. One silent fix makes every other quote in\n    the deliverable suspect.\n17. **Manufacturing a citation for a claim that has none.** If one item in a\n    mapping has no supporting provision in the retrieved sources, put it in a\n    Gaps section and name where the real authority probably lives. Reaching for\n    a near-miss cite is the fastest way to lose a domain reader.\n18. **Presenting a discretionary catch-all as an enumerated ground.** Provisions\n    like \"such other information as the agency, in its discretion, determines\n    appropriate\" are honest authority but weak — label them as such rather than\n    implying a specific named factor supports the claim.\n19. **Rebuilding a retired artifact from memory.** A checklist/form named in the\n    request may have been superseded (SBA's 10-tab purchase checklist → the\n    Universal Purchase Package). Verify current-vs-legacy in the governing SOP\n    and report the supersession instead of reconstructing the old one.\n16. **Choosing a primary key that is null on part of the file.** Measure the null\n    rate of every candidate key before adopting it. A regulator-issued identifier\n    (FDIC cert, NCUA charter, CMS CCN) is only issued to entities that regulator\n    covers, so keying on it silently deletes everyone outside that perimeter —\n    and **the excluded population is usually the analytically interesting one**\n    (non-depository lenders, non-participating providers, unregulated\n    intermediaries). Their *absence from the identifier system is itself a\n    finding*, since it means no examination regime and no prudential backstop.\n    Key on the program's own always-present identifier; attach regulator IDs as\n    optional 0..1 enrichment.\n17. **Accepting an LLM-proposed schema without diffing it against the real\n    header.** Assistants confidently assert plausible fields — loan number, EIN,\n    UEI, borrower ID — that do not exist in the file, often because they are\n    describing a *sibling* dataset from the same agency. Diff every proposed\n    field against the actual header before designing on it, and re-diff after\n    each revision; the same phantom field tends to reappear. Beware naive\n    substring checks: searching for `ein` matches `FixedorVariableInterestInd`.\n19. **Reading a 0% join match rate as \"these keyspaces are unrelated.\"** Sibling\n    datasets from the same agency serialize the same ID at different widths —\n    7(a) FOIA has `0057328`, PPP has `57328`. A naive string join matched\n    **0 of 3,438**, which reads as \"no crosswalk exists\" and would have produced\n    a flatly wrong deliverable. **Exactly zero matches is a bug signal, not a\n    data signal** — genuinely unrelated keyspaces still collide a few times.\n    Normalize (`strip().lstrip(\"0\")`, or cast to int) and re-test before\n    concluding anything, and check the neighbours: whitespace, case, and numeric\n    IDs silently read as `57328.0` by pandas when the column has nulls. In any\n    pipeline built on the join, assert a coverage floor so the regression\n    resurfaces as a failed assertion rather than an empty result set.\n20. **Treating HTTP 200 from a Tableau view path as proof the workbook exists.**\n    Tableau Server returns a byte-identical JS bootstrap shell for *any*\n    `/t/<site>/views/...` path — three guessed workbook names all returned 200 at\n    exactly 5,053 bytes, the same shell the one real workbook rendered an error\n    into. Diff response byte counts against a deliberately bogus path before\n    reporting any dashboard URL as verified. Related: hit\n    `/api/<ver>/serverinfo`, which is unauthenticated and confirms the host is\n    Tableau, then **look for a sibling `*-public.*` extract host** serving the\n    plain XLSX behind the dashboards before fighting the JS rendering.\n21. **Letting a UTF-8 decode error kill a multi-GB stream.** Government CSVs are\n    usually latin-1; `sys.stdin` assumes UTF-8 and dies mid-file\n    (`'utf-8' codec can't decode byte 0xbf`), which also takes down curl with\n    `(56) Failure writing output`. Wrap explicitly:\n    `io.TextIOWrapper(sys.stdin.buffer, encoding=\"latin-1\", newline=\"\")`.\n    latin-1 maps all 256 bytes and never raises. Also: write stream parsers with\n    `write_file` and invoke by path — editing a `python3 - <<'EOF'` heredoc with\n    `sed -i ''` is brittle and silently ships a broken script.\n22. **Assuming a documented field comes with a documented code list.** SBA's\n    dictionary fully enumerates `ProcessingMethod` (18 codes), `LoanStatus` (5),\n    and `RevolverStatus`, but gives `BusinessAge` a prose definition and no\n    values at all. Enumerate empirically and report the omission as a\n    documentation defect instead of quietly inventing the domain. While reading\n    indicator fields, watch for **latch language** — `SoldSecMrktInd` is\n    documented \"once it is 'Y' it will stay 'Y'\", so it means *ever sold*, never\n    *currently held*.\n23. **Believing the docs page's own links to its machine-readable spec.** A\n    Swagger-UI SPA serves relative `href`s to `swagger.yaml` /\n    `*_properties.yaml`, and its catch-all returns the **HTML shell** for every\n    one of them at HTTP 200. Nine FDIC spec filenames all came back at\n    byte-identical 33,612 bytes — identical sizes across supposedly different\n    files is the tell (same trap as the Tableau shell in #20). Follow the site's\n    own 301 (`banks.data.fdic.gov` → `api.fdic.gov/banks`) and re-request the\n    specs from the redirect target, where they return real YAML at real\n    differing sizes. Corollary: always `curl -sSL`; without `-L` you get the bare\n    string `Moved Permanently. Redirecting to ...` and a JSON parser that dies\n    with a misleading `Expecting value: line 1 column 1`.\n24. **Assuming a comma means OR in an Elasticsearch-backed `filters` param.**\n    FDIC BankFind takes `CERT:(35 OR 39 OR 57379)`. `CERT:(35,39,57379)` returns\n    **`total: 0` with HTTP 200 and no error** — indistinguishable from \"these IDs\n    don't exist.\" Any query-string API that returns a clean 200 and zero rows for\n    a batch you *know* is populated should be re-tested one ID at a time before\n    you conclude anything about the data. Related: encode spaces as `%20`\n    (`quote(v, safe='')`), not `+` from `urlencode`'s default `quote_plus`.\n25. **Declaring a code list undocumented when the API can enumerate it.** FDIC\n    publishes no CHANGECODE reference table, but\n    `agg_by=CHANGECODE&agg_term_fields=CHANGECODE_DESC&agg_limit=500` returned\n    all **41 codes with descriptions and event counts** in one call. Before\n    writing \"the agency does not publish the value list,\" check whether the\n    endpoint supports term aggregation and reconstruct it from the data. Note the\n    response shape is asymmetric — the field in `agg_by` comes back as a value,\n    the one in `agg_term_fields` comes back embedded in the **key** name.\n26. **Collapsing entity termination into a single \"inactive\" flag.** There are\n    three economically distinct exits and the distinction is usually the finding:\n    failure (regulator/insurance fund absorbs), merger (successor exists,\n    re-attribute), and **voluntary liquidation (no successor, no insurance-fund\n    loss — the program guarantor eats it)**. On the SBA lender universe, 21 of 78\n    inactive lenders were voluntary closures with no acquirer, including the\n    single worst loss outlier. Also watch direction: FDIC stamps `223` on the\n    *target* and `810` on the *acquirer*, so a **live** entity carrying the\n    acquirer code has a portfolio blended from two underwriting regimes and its\n    ratios must be split at the acquisition date. And exclude paper-only reorg\n    codes (FDIC `820`, 3,381 events) or you manufacture false attribution breaks.\n27. **Treating a similarly-named ratio and dollar field as interchangeable.**\n    FDIC `NPERFV` is a *percentage* (noncurrent / gross loans); `NCLNLS` is a\n    *dollar amount* in thousands. Asset/deposit/equity fields are **$ thousands**\n    throughout. Check the dictionary's `type`/`title` for units on every metric\n    before it enters a computed ratio.\n28. **Letting a favorable early result stand because you never extended the\n    sample.** The single most expensive error in this class of work: a lift,\n    ranking, or validation computed on the *subset already on disk*, then carried\n    into a deliverable and reused for months. Before any predictive claim ships,\n    download the **full published history** and re-run — agencies routinely\n    publish decades of prior-period files alongside the current one, and doubling\n    the panel is usually one afternoon. When you do extend, **reproduce the\n    original cut first as a pipeline control** so a collapsed signal can be\n    distinguished from a refactor bug; then report every window cutoff you tried,\n    including the failures, and state plainly which prior claims must be\n    retracted. Never re-tune windows, thresholds, or filters toward a nicer\n    number. See `references/outcome-data-analytics-rigor.md` §3b-i, where exactly\n    this move turned a published \"2× enforcement lift\" into AUC 0.44.\n29. **Assuming historical extracts of the same program have a degraded schema.**\n    Reasonable prior, frequently false: SBA's FY1991–1999, FY2000–2009,\n    FY2010–2019, and FY2020–Present 7(a) files carry **identical 42 columns in\n    identical order** — the agency back-fitted the old data to the modern schema,\n    so no mapping layer is needed. Diff the headers before budgeting for\n    reconciliation work. What *does* degrade is **per-field coverage**, and it\n    breaks at policy-adoption years rather than file boundaries: `NaicsCode` is\n    ~43–58% populated pre-FY2001 and 99.8%+ from FY2001 (NAICS superseded SIC),\n    while `BankFDICNumber` holds 86.8–92.8% across all eras. Profile null rates\n    **per fiscal year, not per file**, and decide explicitly whether nulls form\n    their own stratum (they should — dropping them deletes a nonrandom era) or\n    disqualify the field.\n30. **Re-parsing a multi-hundred-MB panel for every question.** Assembling\n    ~2M rows across four latin-1 CSVs with `usecols` takes minutes each time and\n    will exceed a foreground call's ceiling. Build the cleaned/derived panel\n    once, persist it (`to_pickle` under the temp dir), and have every subsequent\n    script load that — the enforcement backtest and the vintage analysis here\n    both read one cached frame. Run the build with `background=true` +\n    `notify_on_complete=true`, and confirm the interpreter you are invoking\n    actually has the dependencies *before* launching the long job, since a\n    machine can have several `python3` binaries with different site-packages.\n31. **Concluding a citation doesn't exist after searching only the obvious\n    document.** A prior pass here searched 13 CFR 120, the SOPs, and the Agency\n    Financial Report for SBA's improper-payment corrective actions, found nothing,\n    and recorded \"no citation exists.\" The citation existed — verbatim, agency-\n    certified — on **paymentaccuracy.gov**, the PIIA accompanying materials the\n    AFR is *required to be published alongside*. Before writing \"no primary source\n    supports this,\" enumerate the **companion publications** the governing statute\n    or OMB circular mandates (accompanying materials, scorecards, agency profiles,\n    data appendices), not just the flagship report. And when you do find the real\n    source, grep the flagship for the figure and report the **zero-hit result** —\n    that's what makes the correction defensible rather than merely different.\n32. **Constructing a `.gov` document slug by analogy.** `/document/report-agency-\n    financial-report` is live; the intuitive `/document/report-sba-agency-\n    financial-report` **404s** — the agency-name token is inconsistently present\n    across slugs on the same site. Resolve every slug against the sitemap before\n    fetching, and never treat a 404 on a guessed slug as evidence the document\n    doesn't exist.\n34. **Quoting a regulation without checking whether it changed during the panel.**\n    A section can look settled and have been rewritten mid-dataset — one\n    affiliation test lost three of its five limbs on a single effective date, so\n    identical fact patterns are a rule question before it and no violation after.\n    Pull the amendment history *before* writing the rule into a brief or into\n    code, and retrieve the superseded text from `/on/<date>/`. Related: **a\n    stakeholder-supplied citation is a lead, not a source** — verify the section\n    number, the Part, and the *quantity* the limit is denominated in, because the\n    commonly-quoted figure is often the wrong one of the two. See §4a-bis.\n35. **Assuming a federal registry is FOIA-reachable because it sounds public.**\n    Congress exempts specific registries by statute: FDA's Food Facility\n    Registration list \"shall not be subject to disclosure under section 552 of\n    title 5\" (21 U.S.C. § 350d(a)(4)). Search the authorizing statute for a\n    disclosure clause before running the retrieval ladder, and report the\n    rule-out **with the statutory cite** — a sourced negative reads as domain\n    command; \"I couldn't find it\" reads as an incomplete search.\n36. **Reading a curl exit code instead of the file you just downloaded.**\n    `curl -o report.pdf` against an Akamai-fronted host returns exit 0 and writes\n    an HTML \"Access Denied\" page under a `.pdf` name; `pdftotext` then emits a\n    wall of hex-string syntax errors that look like a corrupt PDF. Run `file` on\n    every downloaded binary before parsing it, and note the recovery: the\n    document's HTML landing page usually carries the Fast Facts, Highlights, and\n    recommendations table through a browser-class scraper, which is often enough\n    without the PDF at all.\n33. **Extracting a multi-column PDF without `-layout`.** OIG executive summaries\n    are two-column; plain `pdftotext` interleaves the columns line-by-line and\n    produces text that looks like corrupted OCR, which reads as \"the PDF is\n    scanned/unparseable.\" `pdftotext -layout` preserves column separation. Check a\n    known-good paragraph before concluding a document needs OCR.\n18. **Joining on a multi-value delimited column with `==`.** Government exports\n    routinely pack several respondents, certs, or docket numbers into one cell,\n    semicolon- or comma-delimited. A naive equality join silently drops exactly\n    the multi-party records that matter most. Split and explode first, then\n    report how many rows the explosion added.\n31. **Digit-stripping a float-typed ID — the worst normalization bug in this\n    class, because it does not produce zero.** Pandas reads a numeric ID column\n    as float, so `str(35.0)` is `'35.0'`, and `re.sub(r'\\D','',...)` yields\n    **`350`** — a *valid-looking wrong key*. It matched 13 of 2,582 lenders and\n    handed back a perfectly plausible \"0.14% FDIC coverage,\" which reads as a\n    finding about unregulated lenders rather than a bug. Pitfall #19's rule\n    (\"exactly zero matches is a bug signal\") does **not** catch this: a partial,\n    believable match rate is the more dangerous failure. Always\n    `str(x).strip().split('.')[0]` before digit-stripping, and treat *any*\n    coverage number well below the documented population as a bug until proven\n    otherwise.\n32. **Fixing a normalization helper at one call site and not the others.** The\n    same float trap lived in both the cert normalizer and the LocationID\n    normalizer; patching one left the other armed, and it was invisible only\n    because that column happened to arrive as a string *in this vintage*. When\n    you fix an ID-normalization bug, fix and unit-test **every** key helper in\n    the pipeline against the same input matrix — float, zero-padded string, bare\n    string, null, empty — then codify coverage floors as in-pipeline `assert`s so\n    the next regression crashes instead of quietly emitting a plausible number.\n33. **Reading a null end-date as \"still active\" — and then explaining the nulls\n    with the wrong mechanism.** Two separate errors, and the second is subtler.\n    FDIC ED&O leaves `Termination Date` null on **79.1%** of rows; the naive\n    reading declared 895 of 898 lenders \"currently under an open enforcement\n    order,\" which is false. But the intuitive diagnosis — \"the agency never\n    backfilled old records\" — is **also false here**, and adopting it produces\n    a *different* wrong answer (discard the old rows, trust the new ones).\n    Restricted to the order types that can actually terminate, the populated\n    rate ran **100% for 1975–89 and 94% for the 1990s, falling to 37.9% for\n    2023–26**: the gradient runs opposite to a backfill gap, because the field\n    tracks a live process (median time to termination 2.01 years). The real\n    cause was **record-type heterogeneity in a pooled file** (#38). Always plot\n    populated-rate by issuance year *within a single record class*, and read\n    the direction of the gradient before naming a cause: falling with age ⇒\n    backfill gap; rising with age ⇒ open cases not yet closed. Either way, the\n    honest label is \"not known to be terminated,\" never \"active.\" Full method,\n    the regulator source map, and the identifier crosswalk are in\n    `references/enforcement-order-status-and-registries.md`.\n\n38. **Deriving a status flag from a pooled registry without splitting record\n    classes first.** One published \"enforcement orders\" file routinely contains\n    three incompatible populations: the orders themselves, **termination events\n    published as their own rows** (not as a field on the order), and action\n    types that have no terminable state at all (money penalties, lifetime\n    prohibitions, applications). In FDIC ED&O that split was 3,295 / 2,859 /\n    4,722 of 10,818 rows — so the denominator for \"is this still in force\" was\n    3,295, not 10,818, and the honest live population was 227 orders on 155\n    institutions rather than \"almost everyone.\" Enumerate the type/category\n    columns and compute the status field's populated rate **per type** before\n    any status logic is written; a rate near 0% for a type means that type has\n    no such state, not that the data is missing.\n\n39. **Not checking a sibling regulator before concluding a concept is\n    undocumented.** FDIC publishes no status filter and no enforcement API\n    endpoint; OCC's search exposes an explicit `terminatedOnly=true` flag and a\n    full CSV/JSON/XML export. Because the two agencies maintain their systems\n    independently, OCC's per-type termination rates (Formal Agreement 99.3%,\n    CMP 0.3%, Prohibition 0.5%) served as an **independent confirmation** of\n    the mechanism inferred from FDIC's file. When a derived-status claim rests\n    on inference from one agency's data shape, go find the peer regulator's\n    version and check the pattern holds before shipping it.\n\n40. **Attributing an action against a person to their employer.** In FDIC ED&O\n    only **21 of 1,952** Removal/Prohibition rows name the institution itself —\n    98.9% name an individual. The bank name is present on every row as\n    *context*, so a naive `groupby(bank)` count of \"enforcement actions against\n    this bank\" is inflated several-fold and is an accusation. Resolve\n    respondent-vs-institution explicitly (normalized-name comparison resolved\n    7,682 of 10,818 rows to institution level) and render the two populations\n    as separate counts, never summed. §8(e)-style bars follow the *person*\n    across employers by operation of law; charter-level orders do not follow\n    the charter's acquirer — see #41 on merger attribution.\n\n41. **Assuming an order transfers to the acquiring institution.** FDIC's own\n    Formal and Informal Enforcement Actions Manual, Chapter 4, contains the\n    word \"successor\" **zero times** across 13 pages; FIL-42-2025 instead makes\n    a merger grounds to *consider termination* (\"the order is no longer\n    applicable to the IDI's current circumstances, including situations in\n    which the IDI is closed, self-liquidated, or merges\"). So an order attaches\n    to the charter it was issued against, a merger does not auto-terminate it,\n    and un-terminated old rows are partly explained by respondents that ceased\n    to exist (24.3% of pre-2010 and 29.4% of 2010–19 null-termination orders in\n    the matched population belonged to now-inactive institutions). Display\n    lineage as \"issued against a predecessor of this institution,\" never as the\n    successor's own order. Proving a doctrine's absence by keyword-scanning the\n    agency's own manual is the citable form of this finding.\n\n42. **Assuming absence of a public enforcement record means absence of\n    enforcement.** Some regulators act entirely non-publicly. A full-text scan\n    of 13 CFR 120 Subpart I (105,392 chars) returned **zero** hits for\n    \"publication,\" \"public notice,\" \"made public,\" or \"publicly\" — SBA lender\n    enforcement is notice-to-lender plus administrative appeal with no\n    publication step, and 13 CFR 120.1060 makes the risk ratings confidential\n    by regulation. Any deliverable covering a mixed population must render \"no\n    public record exists for this entity type\" distinctly from \"no\n    enforcement\"; conflating them manufactures a favorable finding the data\n    cannot support, which is the mirror image of the accusation risk and just\n    as indefensible.\n\n34. **Reporting a match count without naming the unit of analysis.** One registry\n    join legitimately yields three different numbers — **52** borrower-row ×\n    registry-record pairs, **47** distinct borrower rows, **35** distinct\n    borrower entities. The gaps are entities excluded by two agencies, and repeat\n    borrowers holding several loans. Quoting one without saying which turned a\n    4-pre-dating-exclusions headline into a published overcount; the true figure\n    was **3 distinct borrowers**. Print all three units as script output on every\n    run and assert `pairs >= rows >= entities`. See\n    `references/watchlist-match-adjudication.md` §1.\n35. **Treating a status-registry hit as a finding without splitting on effective\n    date.** A match against an exclusion / debarment / sanctions / enforcement\n    list means nothing until the registry's effective date is compared to the\n    event date. Of 52 raw hits, **48 postdated the loan approval** (borrower\n    excluded later — no origination defect) and only 4 predated it. **92% of the\n    raw count was noise**, and the unsplit number is both alarming and\n    meaningless. Then check the outcome field too: two of the three survivors\n    were paid in full, making them *process* exceptions, not loss events.\n36. **Reporting a name match without requiring jurisdiction to agree.** The output\n    of a name match against a watchlist is an accusation. Exact normalized-name\n    matching across 3,316 US lenders returned two hits — both OFAC SDN entries,\n    one with country `XUN` and no address, one in **Moscow** — which would have\n    published that two innocent US community banks were federally sanctioned.\n    Sanctions entries are heavily represented in exclusion registries (23% here)\n    and are overwhelmingly foreign, while generic institution names collide\n    across jurisdictions constantly. Require `country`/`state`/ZIP agreement\n    before reporting any hit, and keep the collisions as a negative control.\n37. **Filtering on a nullable column that the join key already constrains.** A\n    `dropna(subset=['state'])` applied before a name+ZIP5 join was redundant —\n    ZIP5 already pins location — and silently dropped 5 real pairs where `state`\n    was null. Like the float-key bug (#31) it does not error and does not return\n    zero; it returns a *slightly smaller plausible number*. It surfaced only\n    because an independent verification script disagreed with the pipeline by 5.\n    **When two runs disagree by a small amount, never reconcile by assumption** —\n    the first plausible explanation offered here was partially true and not the\n    actual cause. Recompute both under a single definition.\n\n38. **Treating the version of a model or instrument you found as the current\n    one.** A notice that describes itself as \"the Nth redevelopment\" is\n    announcing a *series*, and the member that ranks highest in search is\n    routinely not the newest. **This skill's own knowledge bank carried SBA's\n    2021 Lender Risk Rating model as current for months** while a 2024\n    redevelopment had replaced the method (stepwise regression → XGBoost), the\n    data vendor (D&B → Experian), the segmentation scheme, *and* had published\n    explicit rating thresholds the older notice never stated. It even swapped\n    the meaning of two acronyms between versions, so blending the two produces\n    text that is wrong in a way only a domain reader catches. Enumerate the full\n    lineage (`federalregister.gov/api/v1/documents.json?conditions[term]=<title>`)\n    and cite the newest, noting the ones it supersedes.\n39. **Accepting an outcome variable that a masked population selected for you.**\n    When a public extract redacts the status of the *live* population, whatever\n    terminal state survives becomes the de facto outcome — and any downstream\n    write-up will present that constraint as a design decision. Test it by\n    enumerating the agency's own published metric list and marking each\n    computable or not; if most are not, the project is measuring what leaked.\n    Then look for a provision that *affirmatively declares the surviving field\n    non-confidential* — that converts \"we used the residual\" into \"we used the\n    one dimension the agency decided the public may see.\"\n40. **Assuming a retired input only affects the regulated party.** When an agency\n    discontinues a score, form, or data feed, grep its *own* scorecards, SOPs and\n    review protocols for that input before scoping the impact. A retired input is\n    frequently also a live component of the supervisor's own measurement\n    instrument, so the change degrades the oversight tool as well — which is a\n    far stronger rationale for building a substitute than the first-order effect\n    on the regulated party.\n41. **Inventing strata when the agency publishes its own.** Before defending a\n    peer-cell / cohort / segmentation design, check three separate places: the\n    entity-level **peer groups** the agency benchmarks against (usually size\n    bands), the record-level **segmentation** its model uses (often something\n    non-obvious like data availability), and its **feature list**. An attribute\n    named as a model variable is being conditioned on, not partitioned by —\n    promoting a feature to a stratum and calling it alignment is a common and\n    easily-caught error. Make the agency's grouping primary and yours the stated\n    robustness check, reporting the rank correlation between them.\n\n43. **Answering an as-of-date question from an annual edition.** GPO annual CFR\n    editions are a **Jan-1 snapshot**; eCFR point-in-time is daily. For\n    `13 CFR 120.150` on 2023-06-15 the annual edition said \"SBA will consider\"\n    while the operative text said \"Lenders and CDCs must use appropriate and\n    prudent … commercial credit analysis\" — the amendment had moved the duty\n    onto the lender. Both look authoritative and both cite cleanly, so the\n    substitution is invisible downstream. Use the daily service for any\n    retrospective question, carry a `precision: exact_date | annual_edition`\n    field, and never let the two render identically. Note the point-in-time\n    service has a **historical floor** (Title 13: 2016-12-28) below which it\n    returns 404 with a ~38-byte body — assert the status or you will emit empty\n    chunks that look retrieved.\n\n44. **Assuming a query param filtered because the response looked filtered.**\n    `oversight.gov/api/v2/reports?oig=297`, `?page=1`, and `?items_per_page=5`\n    each returned the **byte-identical** 2,098,080-byte payload — the params are\n    silently ignored. Plausible-looking data comes back either way, so nothing\n    signals the failure. **Diff response byte counts across two different values\n    of the param before trusting it.** Same family as #24 (comma-vs-OR returning\n    a clean empty 200) and #20/#23 (identical byte counts revealing a shell\n    response): identical or unchanged sizes across supposedly different requests\n    is the tell.\n\n45. **Using an aggregator as the corpus spine without measuring its coverage\n    against the publisher.** oversight.gov held 60 SBA OIG reports; the agency's\n    own `sitemap.xml` held **373** — the aggregator covers ~16% and its window is\n    fixed, but it is complete-*looking* and has better metadata (product type,\n    recommendation counts, questioned costs), which is exactly what makes it\n    tempting as the base. Publisher index = spine, aggregator = enrichment joined\n    on identifier. Also: a 200 from a plausibly-named feed proves nothing about\n    its contents — that site's `rss.xml` returns site news, not reports.\n\n46. **Trusting a file's extension and content-type over its bytes.** Federal\n    Register's `raw_text_url` serves `Content-Type: text/plain` at a `.txt` URL\n    and returns a body beginning `<html><head><title>…</title></head><body><pre>`.\n    Name, extension, and header all agree and all mislead, so the HTML wrapper\n    flows straight into the corpus as content. Prefer `full_text_xml_url`. In the\n    same family: a flagship policy document may be **.docx**, not PDF, and\n    `python-docx`'s `document.paragraphs` **silently drops every table** — 23 of\n    them in SBA SOP 50 10 8, holding the eligibility matrices. Walk\n    `document.element.body` instead. No error is raised in either case.\n\n47. **Using a per-page header string as a document-level integrity check.**\n    `EXPIRES: 3/1/27` is printed in the header of every page of an SBA procedural\n    notice, so its occurrence count equals the **page count** — 4 in a 4-page\n    notice, 5 in a 5-page one. \"EXPIRES appears 4 times\" looks like a real\n    assertion and fails on every notice of a different length. Parse and assert\n    on the **value**, never the count.\n\n## Verification checklist\n\n- [ ] Real files downloaded, byte counts and row counts reported.\n- [ ] Actual header printed; at least one
