## 2. The traced-prefix cache (992163d)

`Forecaster._traces` (dispute and bank traces) and both `_masks` now use a new `_DepthCache`:
- Each chain keeps the current path's prefixes on a stack, one per depth, and nothing evicts them.
- Re-reading an ancestor (a parent's mask, a re-read of a prefix) leaves the stack alone.
- An entry that leaves the path (a sibling probe, the path just finished) goes to a 64-entry LRU, and comes back to the stack if a later request extends it.

My first version sent the whole stack to the LRU whenever an ancestor was re-read. The synthetic test caught that before commit, and it is fixed. In that test every prefix was traced exactly once and no ancestor was evicted.

**Complexity, from the code:**
- **Before:** one 512-entry LRU shared by every prefix and every probe. An ancestor survived only while fewer than 512 other prefixes were touched below it, and each node touches several probes. So once a subtree was wide enough, reads of its ancestors (`mask_of` recursion, situations, `inside`, `rec`) missed and re-traced: an engine resume, `finish`, and a fingerprint over [draws, days]. Re-traces per path grew with subtree width. `_masks` was never bounded.
- **After:** each request costs at most O(d) cache bookkeeping, with d at most the tree depth (under 60). An ancestor is traced once per visit to its subtree, and `_masks` holds at most depth + 64 entries. It is a cache only, so the tree, node keys and edges are unchanged.
