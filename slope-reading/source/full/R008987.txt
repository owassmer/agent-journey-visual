Send state and typed questions; get structured answers your code can use directly.\nL22: \nL23: Copy page Copy page\nL24: Large language models (LLMs) are designed to produce text for humans to read. When you need a model to make a judgment that your code will consume, that creates a mismatch: you are coercing a text-generation system into outputting structured decisions, then parsing the results back into something your code can depend on. Jev is TypeSafe\u2019s flagship model and the first \ue200cite\ue2023\u2020System One model\ue201 . System One models are built to make fast, structured decisions that software can use directly.\nL25: Jev evaluates typed questions against a state and returns structured results directly. No text generation, no parsing. You get typed values and probability distributions that your code can branch on, sort by, and route with. Choice and Score also return \ue200cite\ue2024\u2020confidence\ue201 , which your code can use to decide whether and how to act on an answer.\nL26: ##\nL27: \nL28: \ue200cite\ue2025\u2020\u200b\ue201 L29: \nL30: TypeSafe primitives\nL31: \nL32: TypeSafe exposes three AI primitives. Similar to software primitives, our AI primitives are modular, composable, structured, reliable, and fast. Each asks a different type of question and returns a different type of answer.\nL33: Question type  | Goal  | Returns\nL34: --- | --- | ---\nL35: \ue200cite\ue2026\u2020Choice\ue201 | Choose an option from a list  | `choice`, `probabilities`, `confidence`\nL36: \ue200cite\ue2027\u2020Score\ue201 | Score the state on a rubric  | `score`, `probabilities`, `confidence`\nL37: \ue200cite\ue2028\u2020Noul\ue201 | Is this statement true?  | `noul` (0\u20131)\nL38: All three question types can be mixed in a single API call. Every question is evaluated in parallel and in isolation against the same state in one go. Adding questions barely changes the response time. Each question is evaluated independently, so adding more questions does not create context-rot.\nL39: ##\nL40: \nL41: \ue200cite\ue2029\u2020\u200b\ue201 L42: \nL43: Atomic questions, composed in code\nL44: System One models work best when each question asks one specific, well-scoped thing. Think of each question as a gut-check determination: the kind of judgment a highly knowledgeable person could make in a few seconds given the right context. If the question you want to ask would require extended reasoning or weighs multiple independent factors, decompose it. Ask each factor as a separate question, then combine the results with logic in your code.\nL45: This keeps each individual evaluation reliable and gives you full control over how dimensions are weighted. For example, instead of \u201crate this startup pitch,\u201d ask separately about market size, technical feasibility, and differentiation. Combine the scores with your own formula.
