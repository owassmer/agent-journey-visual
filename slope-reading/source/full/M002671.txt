## Data shape written

**`page.json`** gains one key, `assumptions`; every other key is byte-identical. It is a list with central first:
```
{id, label, basis, central: bool,
 metrics: {funded, due, collected, unpaid, past_due, frozen_due, petition_p, clawback, peak_outstanding, avg_outstanding},
 daily:   {limit_mean, outstanding_mean, petition_cum_p, frozen_mean, cash_mean, cash_p5, cash_p50, cash_p95, collected_mean, contractual},
 monthly: [{month, drawn, due, collected, past_due, frozen_due, frozen_not_due, clawback, above_need_p5}],
 ordinary: {metrics, daily, monthly},
 paths, questions, jev: {questions, cached, re_asked, spent_usd}}
```
- `metrics` uses the same keys as `paths.scalars`, in whole cents, with `petition_p` to 6 places.
- `ordinary` is the same forecast with the event given no cash effect.
- `label` is written in `scenario.json`. `basis` is the declared text of the scenario or parameter.

**`assumptions.json`** sits beside the run:
```
{run_id, note, variants: [{id, label, central, change: {scenario, sens}, paths, jev,
  headline: {contractual_cents, collected_cents, uncollected_horizon_cents, stayed_claim_cents, not_yet_due_cents,
             petition_p, preference_exposed_cents, drawn_cents, raise_share, survival_share, floor_share, first_floor_median},
  vs_central: {same keys, the numeric difference from central; null for central}}]}
```

**Probability sliders work on every variant, cheaply.** Each variant's reweight state is at `var/analysis/<run>/assumptions/<id>.page_state.pkl.gz` (about 6 MB compressed). `/runs/<id>/reweight` now takes `{"assumption": "<id>", "overrides": {...}}` and returns the tiles as well as the daily and monthly series, because the browser's path arrays belong to central. A first load takes 0.2 s and each slider move 0.05 s; an unknown id returns 404.

**The page script itself doesn't use any of this yet.** I added no picker to `page.js`, so the variants are in the data and on the endpoint but not on screen.
